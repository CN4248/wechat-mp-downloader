# 微信公众号图片下载器（wxmp）

> **截图说明**：本仓库 README 中的界面图均为 **容器实际运行的测试数据截图**，示例内容（任务名、文件名、链接、账号等）全部为本地生成的测试数据，不含任何真实链接、账号信息或视频画面。

一个专门下载 **微信公众号文章里的所有图片与动图原图** 的工具，提供六种用法：

| 形态 | 说明 |
| --- | --- |
| **Docker Compose + WebUI** | 一条命令起容器，浏览器操作，端口 `2178` |
| **Windows `.exe`** | 双击打开 WebUI，或命令行批量下载 |
| **Android `.apk`** | 手机粘贴链接直接下载，可自选保存目录 |
| **Go 单文件 CLI** | Linux/macOS/Windows 通用，适合脚本、NAS、服务器 |
| **油猴脚本（独立版）** | 在文章页/合集页直接下载，完全在浏览器本地运行，不依赖电脑端程序 |
| **油猴脚本（推送版）** | 文章页/合集页勾选后推送到本机 Docker 或 exe 的 WebUI 下载 |

核心能力：解析 `#js_content` 正文图片、图片消息的 `picture_page_info_list`、GIF 动图、封面；把 WeChat CDN 的缩略图 URL 自动换成 **`/0` 原图**；支持自定义下载目录与自定义重命名规则（含中文变量、`/` 建子目录）；支持 **公众号文章合集批量下载**（WebUI / CLI / APK / 两个油猴脚本）；WebUI 支持 **定时追更**（盯合集或公众号，发现新文章自动下载，每个追更任务可单独设置下载目录与重命名规则，改规则会连带重命名已下载文件）和 **下载任务队列**（暂停/继续/取消/重试/批量操作）。

> 下面 README 引用的界面图全部为 **容器实际运行的测试数据截图**，示例账号、链接与内容均为本地生成的测试数据。

## 1. 快速开始

### 1.1 Docker Compose（推荐）

宿主机要求：Docker 20.10+、Docker Compose v2。

```bash
cd wechat-mp-downloader
cp .env.example .env        # 可选：修改下载目录与端口
docker compose up -d --build
```

打开 <http://127.0.0.1:2178>。

默认配置：

- 端口：`2178`（容器内 `0.0.0.0:2178`，宿主 `${WEB_PORT:-2178}`）
- 网络：`network_mode: bridge`
- 下载目录：宿主 `./downloads` → 容器 `/download`（`.env` 里的 `DOWNLOAD_DIR`，可改成任意绝对路径）
- 额外下载目录：宿主 `.env` 的 `FANBOOK_DIR` → 容器 `/fanbook`（可选；下载目录填 `/fanbook` 或它的子目录即可落到这个挂载点）
- 数据目录：宿主 `./data` → 容器 `/data`（任务历史 / 追更任务）
- 重启策略：`unless-stopped`
- 健康检查：`wget -qO- http://127.0.0.1:2178/api/health`

镜像默认直接复制预编译的静态二进制（`build/wxmp-linux-amd64`），**构建通常只要几秒**，不会在容器里下载 Go 依赖。源码构建走 `Dockerfile.source`。

```bash
# 只重建镜像、不启动
docker compose build

# 看日志
docker compose logs -f wxmp

# 停止
docker compose down
```

> 想换下载目录就改 `.env` 里的 `DOWNLOAD_DIR`（相对/绝对路径都行）；路径含中文/空格没问题，Compose 会原样挂载。WebUI 的目录输入框会把容器内可写目录作为候选项提示（`/api/config` 的 `download_roots`）。
>
> 需要第二个下载位置时（例如漫画 / 同人本目录），在 `.env` 里设置 `FANBOOK_DIR`，它会被挂载到容器内的 `/fanbook`；在 WebUI「下载目录」或推送版面板里填 `/fanbook`（或子目录）即可。容器内的 `/fanbook` 与 `/download` 是两个独立挂载点，互不影响。

### 1.2 Windows `.exe`

1. 解压/复制 `dist/wxmp-windows-amd64.exe`（可改名 `wxmp.exe`）。
2. 双击 → 自动启动本地 WebUI 并打开浏览器（默认 `http://127.0.0.1:2178`，下载目录为 exe 同级的 `downloads`）。
3. 或命令行：

```bat
wxmp.exe -o "D:\公众号图片" "https://mp.weixin.qq.com/s/xxxx"
wxmp.exe -o "D:\公众号图片" -name "<文章标题>/<文章id>-<图片序号>.<扩展名>" -j 8 链接1 链接2
wxmp.exe -dry-run 链接        :: 只预览，不下载
```

### 1.3 Android `.apk`

```bash
adb install -r dist/wxmp-android.apk
```

或把 APK 传到手机点击安装（允许“安装未知来源应用”）。

使用：粘贴文章链接 → **选择目录**（可选，默认 App 专属目录，无需存储权限）→ 需要时改命名规则 → **解析文章** → **开始下载**。

- 目录选择走 SAF（`ACTION_OPEN_DOCUMENT_TREE`），授权持久化，重启后仍有效。
- 支持“附带封面”“覆盖已有”“取消”。
- 默认保存到 `/sdcard/Android/data/com.wxmp.downloader/files/wxmp`。

> Android 端与 WebUI 共用同一套核心逻辑（解析、命名、下载、合集），界面为原生 Java 实现。
> 为避免收录真实公众号内容，这里不放 Android 界面截图，可自行构建 APK 查看。

### 1.4 命令行（Linux / macOS / Windows）

```bash
# 下载到当前目录下的 downloads
./wxmp "https://mp.weixin.qq.com/s/demo1234567890ab"

# 自定义目录 + 默认命名
./wxmp -o /data/pics "https://mp.weixin.qq.com/s/xxxx"

# 中文子目录命名
./wxmp -o /data/pics -name "<文章标题>/<文章id>-<图片序号>.<扩展名>" 链接

# 预览（不落盘）
./wxmp -dry-run -v 链接

# 交互式启动 WebUI
./wxmp -web -listen 0.0.0.0:2178 -o /download
```

不带任何参数运行 = 启动 WebUI（与双击 exe 行为一致）。

### 1.5 油猴脚本（Tampermonkey）

1. 安装 [Tampermonkey](https://www.tampermonkey.net/)。
2. 新建脚本，粘贴 `userscript/wxmp.user.js` 全部内容，保存。
3. 打开任意公众号文章（`https://mp.weixin.qq.com/s/...`），右下角出现 **“下载本文图片 N”** 悬浮按钮。
4. 可改命名规则、勾选“打包为 ZIP”“附带封面”，点开始下载。

脚本完全独立运行：只读取当前页面 DOM，图片走 `GM_xmlhttpRequest` 带 Referer 下载，保存用浏览器原生下载或 File System Access（可选择文件夹），不连接任何本地服务；配置存在 `GM_setValue("wxmp.cfg.v1")`。

> **子文件夹注意**：命名规则里的 `/` 只有在点 **“选择文件夹”**（File System Access）后才会创建子目录；未选择文件夹时走浏览器下载，浏览器不允许网页创建目录，`/` 会被替换成 `_`——例如 `/bilidown/<title>-<post_id>-<order>.<ext>` 会得到 `bilidown_<标题>-<id>-<序号>.<ext>`。需要保留目录结构时：选文件夹、勾选“打包为 ZIP”（压缩包内保留子文件夹），或改用推送版让服务端建目录。

**正文媒体多选**：面板里勾选 **“多选模式”**（默认关闭）后，正文里的图片、动图、视频都可以直接点选；被选中的媒体会盖上绿色高亮框和 **“✓ 已选”** 标记，再点一次取消。选好后点 **“下载所选（N 项）”** 即可按上面的命名规则直接保存到“选择文件夹”指定的位置（没选文件夹时走浏览器下载）。多选命名与整篇下载完全一致：命中正文解析的图片沿用它在文章里的 `<order>`，例如只选第 3 张时文件名仍是 `<标题>-<id>-3.gif`；解析外的视频接在正文序号之后。

![独立版正文多选](docs/userscript-pick-standalone.png)

**合集页多选**：脚本也匹配 `https://mp.weixin.qq.com/mp/appmsgalbum*`，合集页右下角有 **“合集批量下载”** 悬浮按钮，点开的小窗口里可以：
- **选择保存位置**（File System Access，直接写入所选文件夹，保留子目录）；
- **填写重命名规则**（与单篇同一套变量，`/` 建子文件夹）；
- 点 **“进入多选模式”**（默认关闭），勾选多篇后 **“批量下载所选文章”**。

不装浏览器也能跑核心自测：

```bash
node --check userscript/wxmp.user.js
node userscript/test.js        # 使用 testdata/article-fixture.html 断言解析、/0 原图、去重、命名
```

### 1.6 油猴脚本（推送终端版）

`userscript/wxmp-push.user.js` 与独立版**分开保存**，适合 NAS / 常开 Docker 下载：

1. 先在 Docker 或 exe 上启动 WebUI（默认 `http://127.0.0.1:2178`）。
2. 安装脚本，打开公众号文章页，右下角 **“推送到终端”**。
3. 面板里填 **服务地址（终端 IP:端口）**、**服务端下载目录**、**重命名规则** → 保存 → **推送当前文章**。脚本把 `out_dir`、`name_template` 一起发给 `/api/download`，服务端按你填的目录/规则落盘。
4. 合集页右下角有 **“推送到终端”** 悬浮按钮（位置比独立版高，两个脚本同装也不重叠），点开的小窗口里有同样的地址/目录/规则设置，再进入多选模式 → 勾选文章 → **“批量推送所选”**。

**正文媒体多选推送**：文章页面板里也有 **“多选模式”**，点选正文中的图片 / 动图 / 视频（选中项显示蓝色高亮框和 **“✓ 已选”**），点 **“推送所选（N 项）”** 后脚本把 `pick.page_url` 与所选媒体地址发给 `/api/download/media`；服务端读取文章、按**与整篇下载相同的命名规则**渲染文件名并落盘，多选只下载被点中的项。该接口需要本版本的 Docker 镜像 / exe，旧版本会返回 404（脚本会提示更新）。

![推送版正文多选](docs/userscript-pick-push.png)

> **路径注意**：推送版填的是**服务端视角**的路径。Docker 里宿主目录 `./downloads` 挂载为容器内的 **`/download`**，所以这里要填 `/download`（或它下面的子目录），不能填宿主绝对路径；Windows exe 则直接填本机路径，如 `D:\公众号图片`。只填服务地址、不填目录时，服务端会用它的默认下载目录。

两个脚本互不依赖，可同时安装；推送版只发链接/媒体地址，独立版在浏览器本地保存。

## 2. 命名规则（重点）

默认规则：

```text
<文章标题>-<文章id>-<图片序号>.<扩展名>
```

等价英文写法：

```text
<title>-<post_id>-<order>.<ext>
```

渲染示例：`示例文章标题-demo1234567890ab-1.png`。

### 2.1 变量表

| 变量 | 中文别名 | 含义 | 示例 |
| --- | --- | --- | --- |
| `<title>` | `<文章标题>` | 文章标题 | 示例文章标题 |
| `<post_id>` | `<文章id>` | 文章短链 id（`/s/` 后面那串） | demo1234567890ab |
| `<order>` | `<图片序号>` | 图片序号，从 1 开始 | 3 |
| `<order2>` | `<序号2>` | 两位补零序号 | 03 |
| `<ext>` | `<扩展名>` | 扩展名，不含点 | png |
| `<account>` | `<公众号>` | 公众号名称 | 示例公众号 |
| `<author>` | `<作者>` | 作者 | 示例作者 |
| `<date>` | `<日期>` | 发布日期 | 2026-10-21 |
| `<time>` | `<时间>` | 发布时间 `HHMMSS` | 173000 |
| `<year>` | `<年>` | 发布年份 | 2026 |
| `<month>` | `<月>` | 发布月份 | 10 |
| `<day>` | `<日>` | 发布日 | 21 |
| `<kind>` | `<类型>` | `image` / `gif` / `video` | image |
| `<width>` | `<宽>` | 原图宽度 | 1254 |
| `<height>` | `<高>` | 原图高度 | 1254 |
| `<biz>` | — | 公众号 biz | MzkwMDAwMDAwMA== |
| `<sn>` | — | 文章 sn | 3c28e0d4... |
| `<mid>` | — | 文章 mid | 2247523869 |
| `<idx>` | — | 文章 idx | 1 |
| `<file_id>` | — | 微信图片 fileid | 100040218 |
| `<source>` | — | `content` / `picture` / `cover` | content |

不写 `<ext>` 时程序会自动补真实扩展名。

### 2.2 用 `/` 创建子文件夹

```text
<文章标题>/<文章id>-<图片序号>.<扩展名>
```

实际保存为：

```text
/download/示例文章标题/demo1234567890ab-1.png
/download/示例文章标题/demo1234567890ab-2.jpg
```

也可以多层：

```text
<公众号>/<日期>/<文章标题>/<order2>.<ext>
→ /download/示例公众号/2026-10-21/示例文章标题/01.png
```

规则说明：

- `/` 和 `\` 都视为目录分隔符；每一段单独做非法字符清洗。
- 文件名禁止的字符 `< > : " | ? *`、控制字符会被替换为 `_`；Windows 保留名（CON、NUL 等）自动加 `_`。
- 模板渲染后的相对路径不允许越出下载根目录（`..` 会被清洗并通过 `filepath.Rel` 双重校验）。
- 同名文件默认跳过；`-force` / “覆盖已有”才覆盖；同一批内重名会自动加 `-2`、`-3`。

### 2.3 合集命名规则（单独设置）

下载公众号文章合集时使用独立模板，默认：

```text
<collection_title>/<collection_order>-<title>/<post_id>-<order>.<ext>
```

中文写法：

```text
<合集标题>/<合集内文章序号>-<文章标题>/<文章id>-<图片序号>.<扩展名>
```

除单篇全部变量外，新增：

| 变量 | 中文别名 | 含义 | 示例 |
| --- | --- | --- | --- |
| `<collection_title>` | `<合集标题>` | 合集标题 | 示例合集 |
| `<collection_id>` | `<合集ID>` | 合集 id（链接里的 `album_id`） | 9876543210 |
| `<collection_order>` | `<合集内文章序号>` | 文章在合集内的序号（1 = 最早，越大越新） | 106 |

示例输出：

```text
/download/示例合集/106-示例文章标题/1000000001-1.png
/download/示例合集/106-示例文章标题/1000000001-5.gif
```

`/` 同样建子目录；合集模板在 WebUI、CLI（`-collection-name`）、APK 里都可单独修改。油猴脚本多选下载沿用**单篇**规则，不额外使用合集模板。

正文媒体多选（两个油猴脚本）使用与整篇下载**完全相同**的模板和变量取值：`<order>` 取该媒体在文章里的序号（不是“第几个选中”），所以同一张图无论整篇下载还是多选下载都会得到同一个文件名；服务端推送版还会用文章解析结果覆盖扩展名、宽高与 `<kind>`，保证与整篇下载一致。

## 3. 功能细节

- **只取原图**：正文 `data-src` 常以 `/640?wx_fmt=jpeg` 结尾，程序把最后一段尺寸替换成 `/0`，拿到公众号图床保存的原始尺寸（实测 1080×1080 → 1254×1254，1080×1525 → 2508×3541）。
- **GIF 动图**：识别 `data-type="gif"`、`wx_fmt=gif`、`.gif`，按 `gif` 类型保存，保留动画帧；GIF 的 `/0` 同样是原图。
- **图片消息**：除普通图文外，支持 `picture_page_info_list` 形式的图片消息；只取每个条目自己的顶层 `cdn_url`，不会误取 `watermark_info` 水印图。
- **顺序与去重**：以正文 `#js_content` 出现顺序为准，按 CDN host+path 去重；`picture_page_info_list` 中重复的图不会重复下载。
- **封面可选**：默认不下载封面；CLI `-cover`、WebUI 勾选“附带封面”、油猴勾选“附带封面”。
- **内嵌视频（实验性）**：`-video` / “尝试视频”会在页面里探测直接视频地址与 `mpvideo` 计数；微信视频多需专用接口，失败会给出提示而不影响图片。
- **健壮下载**：并发 1–16（默认 4）、每张 3 次重试、`.part` 临时文件原子改名、真实文件头校验、按真实尺寸/格式修正扩展名、MD5 记录、失败不影响其它图片。
- **跳过已存在**：按目标文件名判断，已存在且非空即跳过；`-force` 覆盖。
- **合集批量**：识别 `mp/appmsgalbum` 链接，解析 `window.cgiData` 首屏 + JSON 分页接口，**整册枚举**（不设篇数上限，翻到合集末尾或接口不再前进为止）；WebUI/APK 可先解析出文章列表，CLI 用 `-max-articles` 限制；每篇文章单独解析、下载，合集元数据回填后按合集模板命名。
- **环境异常**：触发微信“环境异常”验证页时，会提示先在浏览器打开一次文章（或提供 Cookie），不会把验证页当图片保存。

### 3.1 定时追更（1.3.0 新增）

**能追什么**（三种追更方式，添加时可选）：

| 方式 | 添加方式 | 扫描方式 | 需要 Cookie |
| --- | --- | --- | --- |
| **合集 / 文集** | 粘贴合集链接 | 官方 `appmsgalbum` JSON 分页，只翻到「已见过」的位置为止 | 否 |
| **公众号 · 公开合集** | 粘贴该号任意一篇文章链接 | 用文章页 `album_info` 发现该号的公开合集，逐个合集扫描 | 否 |
| **公众号 · 全部文章** | 粘贴该号任意一篇文章链接（或从搜索结果点「追更全部文章」） | `profile_ext?action=getmsg` 逐页拉取该号文章列表，**每发一篇就追一篇** | **是**（含 uin/key） |

> 微信对匿名访问只公开「合集」文章列表；「全部文章」必须带微信登录态（`uin` + `key`），这是微信的平台限制，不是本工具的选择。没有 Cookie 时任务会创建但扫描会明确报错提示，不会假装成功。

**微信 Cookie 怎么填**：WebUI「定时追更 → 微信 Cookie」里粘贴（**只存内存，不落盘、不写日志**，容器重启后需重填）；也可以启动容器时设环境变量 `WXMP_COOKIE="uin=...; key=...; wap_sid2=..."`（写在宿主的 shell/未入库的 env 里，别提交到仓库）。Cookie 需包含 `uin`、`key` 两项，界面会显示「已设置（含 uin/key）」。

**首次扫描**：默认只建立基线（把现有文章记为已见），之后只下载新发布的文章。想补下历史，在添加时填「首次补下最近 N 篇」。

**下载起点（含起点自身）**：每个追更任务可以指定「从哪一篇开始下载」——

- 点任务里的「选择起点」会列出该合集（公众号任务则是各合集）最近的文章，选一篇确认即可；
- 含义是**包含这一篇、向更新的方向**下载；更早的文章不会下；
- 设置后**整册枚举**并立即从起点补下（不设篇数上限，一次可覆盖整册；按 30 篇一个任务排队），起点之前的老文章会一并记为已见，之后回到「只追新文章」；
- 起点原文若已被作者删除，会按它的发布时间兜底补下，并在提示里注明「起点原文已不在合集里」；
- 「按起点补下」可重跑（已存在的文件会跳过），「清除起点」则恢复为只追新文章并重建基线。

![选择下载起点](docs/webui-start-picker.png)

![按篇追更与 Cookie](docs/webui-author-follow.png)

**独立设置**：每个追更任务都有独立的

- 重命名规则（`template`）：留空＝默认规则；合集默认为合集规则，公众号默认为单篇规则；
- 下载目录（`dir`）：留空＝默认目录；
- 扫描间隔（分钟，0＝跟随全局）。

**改规则会连带改名**：每个已下载文件都记录了当时的模板变量快照。修改追更任务的重命名规则后，程序立刻按新规则重命名这些老文件；**原文件已不存在（作品被删、被手动移走）的跳过并保持原样**，界面会提示「N 个文件已不存在，保持原样」。

**限制与礼貌**：

- 合集若是「倒序」（旧→新）排列，新文章在列表末尾：程序会按发布时间自动识别并多翻几页（最多 10 页），仍翻不到时在提示里注明「下轮继续」；
- 扫描是**串行**的，两次扫描之间至少间隔 `min_gap`（默认 60 秒），并在每轮加随机抖动；
- 单轮最多下载 `max_new` 个（默认 10），剩下的下一轮继续；
- 定时器只在任务启用且到点时才扫，不并发打同一个接口。

### 3.2 下载任务队列（1.3.0 新增）

- 任务进队列后串行执行，可随时 **暂停**（当前文件下载完就停，已下载的保留）、**继续**（重新排队，已存在的文件跳过，不会重复下载）、**取消**、**重试**。
- 支持「暂停全部 / 开始全部 / 重试所有失败 / 删除已完成任务」，也支持勾选若干任务后批量暂停、开始、取消、重试、删除。
- 删除任务只删记录，**不会删除已下载的文件**；「删除已完成任务」保留失败任务，方便再试。
- 通过链接下载时，解析出来的每篇文章/合集都可以在自己的卡片里**临时**改下载目录与重命名规则；不改就跟随全局设置。

## 5. 构建

### 5.1 Go 二进制

```bash
go build -trimpath -o wxmp ./cmd/wxmp

# Linux 静态（容器用）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o build/wxmp-linux-amd64 ./cmd/wxmp

# Windows
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dist/wxmp-windows-amd64.exe ./cmd/wxmp
```

`scripts/build.sh` 会一次性完成 gofmt 检查、`go vet`、单测、Linux/Windows 交叉编译并注入版本号。

### 5.2 Docker 镜像

```bash
# 快速构建（复制 build/wxmp-linux-amd64）
docker compose build

# 完全源码构建（容器内编译）
docker build -f Dockerfile.source -t wechat-mp-downloader:source .
```

### 5.3 Android APK

无需 Gradle，使用 Android SDK 命令行工具：

```bash
export ANDROID_SDK_ROOT=/opt/android-sdk
export JAVA_HOME=/opt/jdk21
bash android/build-apk.sh
# 产物：dist/wxmp-android.apk
```

脚本流程：`aapt2 compile → aapt2 link → javac --release 8 → d8 → zip 注入 classes.dex → zipalign → apksigner`。首次会自动生成 `android/wxmp-release.keystore`（alias `wxmp`，口令 `wxmp123456`，仅用于本地测试签名）。

> 注意：本仓库的 Android 代码不使用匿名内部类与 lambda，全部用具名 static 嵌套类 + `Handler`；这是为了绕开 build-tools 34.0.0 的 d8 在解析 javac 21 匿名类时的 NPE。

## 7. 常见问题

**Q：提示“环境异常/访问过于频繁”？**
微信对匿名请求有风控。先用浏览器打开该文章一次，再把浏览器 Cookie 传给 CLI：`wxmp -cookie "..." 链接`，或设置环境变量 `WXMP_COOKIE`。WebUI 的 Cookie 支持在服务端配置（不落盘）。

**Q：合集链接怎么用？**
直接粘贴 `https://mp.weixin.qq.com/mp/appmsgalbum?...&album_id=...`。WebUI/APK 会显示合集文章列表；CLI 加 `-max-articles 2` 只下前 2 篇。合集命名规则在 WebUI「合集重命名规则」、CLI `-collection-name`、APK 合集规则输入框里单独设置。

**Q：命名规则里写了 `/bilidown/...`，为什么文件名变成 `bilidown_...`、也没建子文件夹？**
浏览器原生下载只能落到下载目录的一个文件，网页/油猴脚本无法在磁盘上随意建目录，所以脚本会把 `/` 替换成 `_`。想保留 `/` 的层级：先在面板点 **“选择文件夹”**（Chrome / Edge 支持，文件会写入该文件夹并自动创建子目录），或勾选 **“打包为 ZIP”**（压缩包内保留子文件夹），或改用推送版由服务端创建目录。规则里的前导 `/` 不是磁盘根路径，而是相对于所选文件夹 / 服务端下载目录。

**Q：221 篇的合集只解析到 220 篇 / 提示“合集分页解析失败：cannot unmarshal object into … article_list”？**
这是微信接口在**最后一页只剩 1 篇**时把 `article_list` 序列化成对象而不是数组导致的，不是篇数上限；已修复（旧镜像/exe 需要更新）。修复后程序会继续翻到合集末尾，例如 221 篇的合集实测解析到 221 篇（含最老的 `pos_num=1`）。

**Q：两个油猴脚本装哪个？**
想完全在浏览器本地保存（可打包 ZIP、可选文件夹）装 `wxmp.user.js`；想把手上的链接交给常开的 Docker/exe 去下载装 `wxmp-push.user.js`。二者互不依赖，可同时装。

**Q：下载下来的是缩略图？**
本工具默认把 `/640` 等尺寸段替换为 `/0`。如果某张图在 CDN 上没有原图，`/0` 会返回与页面相同尺寸，这是微信侧的限制。

**Q：动图变成静态图？**
确认保存的扩展名是 `.gif`（预览里有 GIF 徽标）。若文章把动图以视频形式插入，请用 `-video` 尝试视频下载。

**Q：端口 2178 被占用？**
改 `.env` 的 `WEB_PORT`，例如 `WEB_PORT=2180`，然后 `docker compose up -d`。

**Q：容器里“打开目录”没反应？**
容器内无法打开宿主文件管理器，属正常现象；直接去宿主挂载目录查看。本机运行 exe/二进制时该按钮可用。

**Q：按篇追更提示「微信只对登录态开放公众号文章列表」？**
说明还没填微信 Cookie，或 Cookie 里缺 `uin`/`key`。在「定时追更 → 微信 Cookie」粘贴含这两项的 Cookie（仅内存），或启动时给 `WXMP_COOKIE`。没有登录态时请改用「合集」或「公众号 · 公开合集」。

**Q：为什么「搜索公众号作者」搜不到某个号？**
微信没有对外的公众号搜索接口（搜狗微信搜索对匿名请求也不返回结果），所以搜索范围是**本机解析过的公众号**（每解析一篇文章就会记下来）。要追更某个号：直接粘贴它任意一篇文章链接解析并添加；如果它没有公开合集，微信侧无法列举新文章，程序会明确告知。

**Q：追更的公众号新文章没下到？**
公众号追更只能覆盖「公开合集」里的文章。若作者把新文章放在别的新合集里，在追更任务的 `albums` 里补上那个合集链接（或直接再添加一个合集追更）。

**Q：改了追更的重命名规则，老文件没改名？**
文件已不存在（被删/被移走）时按需求保持原样，界面会显示「N 个文件已不存在，保持原样」；只记录**通过追更下载**的文件，手动用链接下载的文件不在追更改名范围内。

**Q：Android 下载到哪？**
默认 App 专属目录，不需要存储权限；可点“选择目录”授权任意文件夹（SAF）。

- 图集与正文“数量相同、尺寸逐项相同”时，整组视为镜像并忽略，即使两边的 hash 完全不同也能折叠。

### 未发布 · 正文媒体多选（2026-11-06）
